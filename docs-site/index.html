Getting started with FoodNow

A small food-delivery backend: browse restaurants, see menus, place an order, track its status. Stack: Node.js 20+, Express 5, PostgreSQL.

1. Get the code

Prerequisites: Git, Node.js 20.6+ (for --env-file) and a running PostgreSQL.

git clone https://github.com/mohamedessamcs96/GIU-Foodnow.git
cd GIU-Foodnow

2. Setup

npm install
cp .env.example .env     # then edit DATABASE_URL with your Postgres password

Create the database and load the tables and sample data:

createdb foodnow_db
psql -d foodnow_db -f sql/schema.sql   # tables (drops existing ones!)
psql -d foodnow_db -f sql/seed.sql     # sample restaurants and menus

Start the server (auto-restarts on file changes):

npm run dev

Open http://localhost:3000/health. You should see {"status":"ok"}. The live docs are at http://localhost:3000/doc/guide.

3. Try it

curl "http://localhost:3000/api/v1/restaurants?open=true"
curl http://localhost:3000/api/v1/restaurants/1/menu

curl -X POST http://localhost:3000/api/v1/orders \
  -H "Content-Type: application/json" \
  -d '{"restaurantId":1,"customerName":"Sara","address":"12 Tahrir St, Giza",
       "items":[{"menuItemId":1,"quantity":2},{"menuItemId":3,"quantity":1}]}'

curl -X PATCH http://localhost:3000/api/v1/orders/1/status \
  -H "Content-Type: application/json" -d '{"status":"preparing"}'

Total = sum of (price x quantity) + the restaurant's delivery fee. Prices always come from the database, never from the client.

4. How a request flows

  1. Global middleware (app.js): helmet (secure headers), cors, morgan (logging), JSON body parser, static files, rate limiter on /api/v1.
  2. Route (routes/): matches the URL and runs validation middleware (validate, validateId). Bad input stops here with 400.
  3. Controller (controllers/): reads req, calls one service function, sends the response.
  4. Service (services/): business rules and SQL. Throws AppError when a rule fails.
  5. Database (db.js): connection pool; withTransaction makes multi-step writes all-or-nothing.
  6. Error handler: turns any AppError into a JSON response with the right status code; unknown errors become a safe 500.

See the diagrams for the visual version, including the ERD and sequence diagrams.

6. Key ideas used in the code

  • Layers: each layer has one job, so a change touches few files.
  • Higher-order functions: asyncHandler, validate(rules), withTransaction(work) take or return functions.
  • Transactions: creating an order saves the order and its items together, or nothing.
  • Price snapshot: order_items.unit_price copies the price at order time so later menu edits don't change old orders.
  • Parameterized SQL: values go in $1, $2, never string-concatenated, which prevents SQL injection.
  • State machine: order status can only move along allowed steps.

8. Troubleshooting

  • "Missing required environment variable: DATABASE_URL": you didn't create .env.
  • "Could not connect to the database": Postgres isn't running, or the password or database name in DATABASE_URL is wrong.
  • Empty restaurant list: run sql/seed.sql.
  • Diagrams don't show: the page loads Mermaid from a CDN, so it needs internet access.
